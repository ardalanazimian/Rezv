#  baselineِ انحرافِ کنشِ کلیدهای خارجی بینِ دو مسیرِ ساختِ اسکیما
#  (مصرف‌کننده: tools/check-schema-drift.sh)
#
#  هر خط یک FK است که `prisma db push` جور دیگری می‌سازد تا
#  `migrate deploy + apply-sql.sh`. این فایل **بدهیِ ثبت‌شده** است، نه وضعِ
#  مطلوب: چک فقط روی انحرافِ *تازه* می‌شکند تا دروازه پرنویز و درنتیجه
#  نادیده‌گرفته‌شده نشود.
#
#  کدها:  a=NO ACTION · r=RESTRICT · c=CASCADE · n=SET NULL · d=SET DEFAULT
#
#  دو الگویِ سیستماتیک که بخشِ عمده‌ی این فهرست‌اند و رفتاری تولید نمی‌کنند:
#    • upd: Prisma روی همه‌ی FKها CASCADE می‌گذارد، SQLِ دستی معمولاً بندِ
#      ON UPDATE نمی‌نویسد. کلیدهای اصلی UUIDاند و هرگز UPDATE نمی‌شوند.
#    • del=r در برابر del=a: هر دو حذف را رد می‌کنند؛ فقط زمانِ بررسی فرق دارد.
#  بقیه (تولید CASCADE می‌کند جایی که Prisma RESTRICT می‌خواهد) تصمیم‌های
#  قدیمیِ همین مخزن‌اند و هرکدام داوریِ محصولی می‌خواهند.
#
#  ⚠️ کوچک‌شدنِ این فایل پیشرفت است. قبل از افزودنِ خطِ تازه مطمئن شو انحراف
#  واقعاً عمدی است — وگرنه به‌جای baseline، مهاجرتِ SQL بنویس.
#
#  تولیدشده: ۲۰۲۶-۰۸-۲۵ روی Postgres واقعی (۶۹ FK در سمتِ Prisma، ۷۱ در تولید)
