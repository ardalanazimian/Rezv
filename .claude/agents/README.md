# تیمِ مهندسیِ رزرونو (subagentها)

> بازنویسی‌شده در ۲۰۲۶-۰۸-۲۳. جایگزینِ عملیِ ۲۱ نقشِ `agency/registry/agents.yaml`.

## چرا بازنویسی شد
`agency/` یک سازمانِ شبیه‌سازی‌شده با ۲۱ نقش بود (CEO، Product، Marketing، Competitive Intelligence، Experimentation، …) که در ۲۰۲۶-۰۸-۱۳ با تصمیمِ صریحِ مالک به‌خاطرِ **مصرفِ بیش از حدِ توکن** `DISABLED` شد.

این تیم همان اشتباه را تکرار نمی‌کند:
- **۶ نقش به‌جای ۲۱** — و هر شش‌تا اجرایی‌اند، نه سِمَتِ سازمانی. نقشی که کد لمس نمی‌کند وجود ندارد.
- مرزها روی **مرزهای واقعیِ ریپو** کشیده شده‌اند (vanilla در برابر React، بک‌اند در برابر پنل)، نه روی عناوینِ شغلی.
- **هیچ حلقه‌ی خودگردانی نیست.** هر ایجنت فقط وقتی اجرا می‌شود که صریحاً صدا زده شود. نه cron، نه trigger، نه پایشِ پس‌زمینه، نه عملیاتِ خودکارِ گیت‌هاب.

⚠️ این تیم `agency/` را **فعال نمی‌کند**. `agency/AGENCY_STATUS` هنوز `DISABLED` است و همان‌طور می‌ماند؛ خودِ آن فایل می‌گوید هیچ عاملی مجاز به تغییرش نیست. آن‌ها دو مکانیزمِ جدا هستند.

## قراردادِ تشدید (هسته‌ی این ساختار)

هر ایجنتِ اجرایی موظف است گزارشش را با این بلوک تمام کند:

```
## حکمِ نهایی
وضعیت: قطعی | مشکوک | ناتمام
شواهد: <چه چیزی واقعاً اجرا/دیده شد>
اثبات‌نشده: <چه چیزی فرض شد>
```

- **قطعی** → کار تمام است.
- **مشکوک** (حل شد ولی با تردید) → به `architect` می‌رود.
- **ناتمام** (حل نشد) → به `architect` می‌رود.

`architect` گزارشِ ایجنتِ قبلی را می‌خواند تا از صفر شروع نکند، ولی **نتیجه‌اش را بدونِ بررسی قبول نمی‌کند** — ایجنت‌ها گاهی نتیجه‌ی غلط برمی‌گردانند.

اعلامِ «مشکوک» تنبیه ندارد. پنهان‌کردنش دارد. یک حکمِ «قطعی»ِ دروغ از یک «ناتمام»ِ صادقانه به‌مراتب گران‌تر تمام می‌شود.

## مرزهای مشترکِ همه
- همه‌ی ارتباط فارسی؛ UI فارسی و RTL با Vazirmatn.
- هرگز نگو «تست شد» مگر واقعاً اجرا کرده باشی. تایپ‌چکِ پاک دلیلِ کارکردن نیست.
- اسکیمای دیتابیس، سیاستِ امنیتی و RBAC هیچ‌وقت خودسرانه عوض نمی‌شوند → تشدید + PR + تأییدِ انسانی.
- هیچ secret/کلید/`.env` واقعی کامیت نمی‌شود.
- داده‌ی فیک/هاردکدی که باید واقعی باشد، حتی بدونِ رفع، ثبت می‌شود.
- اولویتِ اول رفعِ باگِ موجود است، نه قابلیتِ جدید.
