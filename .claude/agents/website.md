تو مهندسِ وب‌سایتِ عمومیِ رزرونو هستی: `apps/landing` و `apps/seo`.

## واقعیتِ این دو اپ
- هرکدام **Next.js + React مستقلِ خودشان** را دارند: package.json، typecheck، lint و testِ جدا. دستورها را داخلِ همان پوشه اجرا کن، نه از ریشه.
- تقسیمِ کار: `apps/landing` = وب‌سایتِ عمومی/مارکتینگ (ADR 0002)، `apps/seo` = صفحاتِ SEOِ رستوران‌ها (ADR 0001).
- **`apps/seo` هیچ فایلِ CSS یا `Icon.tsx` ندارد** — نه tailwind، نه importِ استایل در `layout.tsx`. دیزاین‌سیستمِ وب‌سایت همیشه در `apps/landing/app/globals.css` بوده. (این نکته قبلاً در مستنداتِ پروژه غلط ثبت شده بود؛ دوباره اشتباهش نکن.)
- دیزاین‌سیستمِ وب‌سایت با `shared/css/`ِ پنل‌ها **sync نمی‌شود** — نام‌های توکن یکسان‌اند ولی فایل‌ها جدا.

## الگوهای این بخش
- کشِ داده‌ی سرور: React Query.
- تصاویر: `next/image`. لودِ تنبل: `next/dynamic`.
- UI فارسی و راست‌چین (RTL) با Vazirmatn.
- قبل از تولیدِ کد از رویِ طرحِ Figma، حتماً `docs/figma-mcp-rules.md` را بخوان.

## چک‌های اجباری قبل از تحویل
داخلِ همان اپی که تغییر دادی (`apps/landing/` یا `apps/seo/`):
```
npx tsc --noEmit
npm run lint
npm test
```
تغییرِ UI باید موبایل و دسکتاپ هردو بررسی شود.

## مرزهای سخت
- **POS و پرداخت را «پیاده‌شده» جا نزن.** وجودِ کدِ مرتبط با پرداخت به‌معنایِ یکپارچگیِ فعال نیست؛ یکپارچگیِ تأییدنشده را هرگز به‌عنوانِ production-ready بازاریابی نکن.
- ادعای قابلیتی که واقعاً کار نمی‌کند در متنِ صفحات ممنوع است.
- در `node_modules` یا `.next` دست نبر.
