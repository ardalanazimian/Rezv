# پیش‌نمایشِ آفلاینِ وب‌سایتِ رزرونو

فایلِ `website.html` یک نسخه‌ی کاملِ خودکفا از سایت است: بدونِ سرور، بدونِ
اینترنت، بدونِ نصب. کافی است بازش کنید.

## چطور نشان بدهم

**روی کامپیوتر یا لپ‌تاپ** — روی `website.html` دابل‌کلیک کنید.

**روی گوشی** — فایل را با پیام‌رسان/ایمیل/کابل به گوشی بفرستید، بعد:
- اندروید: از «فایل‌ها» بازش کنید و Chrome را انتخاب کنید.
- آیفون: در «Files» ذخیره کنید و لمس کنید (Safari بازش می‌کند).

پایینِ صفحه یک نوارِ انتخابِ صفحه هست؛ با آن بینِ ۱۲ صفحه‌ی سایت جابه‌جا
می‌شوید. لینک‌های داخلِ خودِ صفحه‌ها هم کار می‌کنند.

## چه چیزی واقعاً کار می‌کند

همان کدِ سایت است، نه یک ماکِت:

- میدانِ جریانِ هیرو (بومِ متحرک با واکنش به اشاره‌گر)
- پرده‌ی ورود، دانه‌ی فیلم، نشانگرِ سفارشی (روی دستگاهِ ماوس‌دار)
- صحنه‌ی سنجاق‌شده‌ی پنج‌فصلی با اسکرول
- شبیه‌سازیِ شبِ سرویس و جریانِ زنده‌ی رزرو
- دستیارِ پرسش‌وپاسخ با پیکره‌ی واقعیِ سایت (۴۹ پرسش + پلن‌ها + مقاله‌ها)
- تمِ روشن/تاریک، منوی موبایل، آکاردئونِ پرسش‌ها

## چه چیزی کار نمی‌کند (و چرا)

هر چیزی که به سرور نیاز دارد: ثبتِ دمو، خرید، فرمِ تماس و داشبوردِ مدیریت.
این‌ها به API و دیتابیس وصل‌اند و در یک فایلِ آفلاین معنا ندارند. محتوای
نمایش‌داده‌شده از فایلِ حالتِ امن (`content/site-content.json`) می‌آید.

## دوباره ساختنش

```bash
cd apps/landing && npm run build && PORT=3200 npm run start &
python3 tools/build-site-preview.py
```

فایل در همین پوشه به‌روز می‌شود.

> نکته‌ی فنی: باندلِ Turbopack روی `file://` بالا نمی‌آید (چانک‌ها را در زمانِ
> اجرا fetch می‌کند). برای همین `apps/landing/preview/mount.tsx` با esbuild به
> یک اسکریپتِ کلاسیک تبدیل می‌شود که *همان* کامپوننت‌های واقعیِ سایت را سوار
> می‌کند — هیچ منطقی دوباره نوشته نشده، پس پیش‌نمایش و سایت از هم واگرا
> نمی‌شوند.
