# نسخه‌ی آفلاینِ رزرونو

از `index.html` شروع کنید — چهار چیز داخلِ همین پوشه است:

| فایل | چیست | تازگی |
|---|---|---|
| `website.html` | وب‌سایتِ عمومی، ۱۲ صفحه | ⚠️ **اسنپ‌شاتِ ۲۰۲۶-۰۸-۲۰** — پایین را بخوان |
| `customer.html` | اپ مشتری | از منبع بازتولید می‌شود |
| `business.html` | پنل رستوران | از منبع بازتولید می‌شود |
| `company.html` | پنل شرکت | از منبع بازتولید می‌شود |

همه بدونِ سرور، بدونِ اینترنت و بدونِ نصب کار می‌کنند.

> ⚠️ **`website.html` با بقیه فرق دارد.** سه فایلِ دیگر را
> `tools/build-standalone.py` از `apps/{customer,business,company}` می‌سازد و
> گیتِ `--check` تازگی‌شان را تضمین می‌کند. `website.html` هیچ سازنده‌ای در
> ریپو ندارد: یک اکسپورتِ دستیِ `apps/landing` است که آخرین‌بار در
> ۲۰۲۶-۰۸-۲۰ (کامیتِ `47e95ce`) گرفته شده و از آن زمان `apps/landing` تغییر
> کرده. پس محتوایش را **نمایشی** حساب کن، نه بازتابِ وضعیتِ امروزِ سایت.
> (ثبت‌شده در `docs/audit/DEAD-CODE.md`؛ از ۲۰۲۶-۰۸-۲۶ خودِ `--check` هم
> صریح اعلامش می‌کند.)
کدِ ورودِ پنل‌ها: **۱۲۳۴**

## گالریِ عکس (تازه)

عکس دیگر با لینک اضافه نمی‌شود؛ فایل مستقیم آپلود می‌شود و تا تأییدِ پنلِ
شرکت هیچ‌جای عمومی دیده نمی‌شود.

- **پنل رستوران ← پروفایل و نظرات ← عکس‌های مجموعه** — انتخابِ فایل،
  پیش‌نمایش، و نشانِ «در انتظار تأیید» روی هر عکس.
- **پنل شرکت ← بازبینی عکس** — صفِ بازبینی با تأیید/رد.

در نسخه‌ی آفلاین، صفِ پنلِ شرکت دادهٔ نمونه‌ی برچسب‌خورده با `[DEMO]` نشان
می‌دهد و دکمه‌های تأیید/رد عمداً کاری نمی‌کنند — تصمیمِ انتشار نباید روی
دادهٔ ساختگی گرفته شود.

## وب‌سایت

فایلِ `website.html` یک نسخه‌ی کاملِ خودکفا از سایت است.

## چطور نشان بدهم

**روی کامپیوتر یا لپ‌تاپ** — روی `website.html` دابل‌کلیک کنید.

**روی گوشی** — فایل را با پیام‌رسان/ایمیل/کابل به گوشی بفرستید، بعد:
- اندروید: از «فایل‌ها» بازش کنید و Chrome را انتخاب کنید.
- آیفون: در «Files» ذخیره کنید و لمس کنید (Safari بازش می‌کند).

پایینِ صفحه یک نوارِ انتخابِ صفحه هست؛ با آن بینِ ۱۲ صفحه‌ی سایت جابه‌جا
می‌شوید. لینک‌های داخلِ خودِ صفحه‌ها هم کار می‌کنند.

## چه چیزی واقعاً کار می‌کند

همان کدِ سایت است، نه یک ماکِت:

- میدانِ جریانِ هیرو (بومِ متحرک با واکنش به اشاره‌گر)
- پرده‌ی ورود، دانه‌ی فیلم، نشانگرِ سفارشی (روی دستگاهِ ماوس‌دار)
- صحنه‌ی سنجاق‌شده‌ی پنج‌فصلی با اسکرول
- شبیه‌سازیِ شبِ سرویس و جریانِ زنده‌ی رزرو
- دستیارِ پرسش‌وپاسخ با پیکره‌ی واقعیِ سایت (۴۹ پرسش + پلن‌ها + مقاله‌ها)
- تمِ روشن/تاریک، منوی موبایل، آکاردئونِ پرسش‌ها

## چه چیزی کار نمی‌کند (و چرا)

هر چیزی که به سرور نیاز دارد: ثبتِ دمو، خرید، فرمِ تماس و داشبوردِ مدیریت.
این‌ها به API و دیتابیس وصل‌اند و در یک فایلِ آفلاین معنا ندارند. محتوای
نمایش‌داده‌شده از فایلِ حالتِ امن (`content/site-content.json`) می‌آید.

## دوباره ساختنش

```bash
cd apps/landing && npm run build && PORT=3200 npm run start &
python3 tools/build-site-preview.py
```

فایل در همین پوشه به‌روز می‌شود.

> نکته‌ی فنی: باندلِ Turbopack روی `file://` بالا نمی‌آید (چانک‌ها را در زمانِ
> اجرا fetch می‌کند). برای همین `apps/landing/preview/mount.tsx` با esbuild به
> یک اسکریپتِ کلاسیک تبدیل می‌شود که *همان* کامپوننت‌های واقعیِ سایت را سوار
> می‌کند — هیچ منطقی دوباره نوشته نشده، پس پیش‌نمایش و سایت از هم واگرا
> نمی‌شوند.
