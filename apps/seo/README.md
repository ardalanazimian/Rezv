# apps/seo — لایه‌ی عمومیِ رزرونو (Next.js SSR/ISR)

> اپِ **جداگانه و ایزوله** برای صفحاتِ عمومیِ ایندکس‌پذیر: رستوران، **منویِ QR**، شهر و آشپزی.
> اپ‌های `customer`/`business`/`company` دست‌نخورده و static می‌مانند.
> مبنا: [`docs/adr/0001-seo-rendering-architecture.md`](../../docs/adr/0001-seo-rendering-architecture.md)
> و [`SEO_AUDIT_REPORT.md`](../../SEO_AUDIT_REPORT.md).

## چرا جدا
این تنها فرانتِ رزرونو است که **build step** دارد (Next.js). SSR/ISR + URLهای per-entity
برای رقابتِ SEO لازم‌اند و در معماریِ static/no-buildِ بقیه‌ی اپ‌ها ممکن نیستند. جداسازی
یعنی خرابیِ اینجا به اپ‌های زنده آسیب نمی‌زند.

## صفحات

| مسیر | چیست | ISR |
|---|---|---|
| `/` | hub — شهرها و سبک‌هایِ آشپزیِ واقعی از API | ۱ ساعت |
| `/r/{slug}` | صفحه‌ی رستوران: نشانی، ساعتِ کاری، گالری، **پیش‌نمایشِ منو**، FAQ، رستوران‌های مشابه | ۵ دقیقه |
| `/r/{slug}/menu` | **منویِ کامل — مقصدِ QRِ روی میز** | ۵ دقیقه |
| `/city/{c}`، `/cuisine/{c}` | صفحاتِ فهرست با گاردِ کیفیت | ۵ دقیقه |
| `/sitemap.xml`، `/robots.txt` | پویا از API | — |

## آدرسِ QR — تصمیم و دلیلش

**QR به `https://rezervno.ir/r/{slug}/menu` می‌رود.** منبعِ واحدِ این آدرس
[`lib/urls.ts`](./lib/urls.ts) است و همتایِ سمتِ سرورش `api/src/lib/public-urls.ts`
(پنلِ بیزنس همان را داخلِ QR می‌گذارد، پس لینکِ کپی‌شده و QRِ چاپ‌شده نمی‌توانند از هم بیفتند).

- **چرا صفحه‌ی منو و نه صفحه‌ی رستوران:** مهمانی که سرِ میز نشسته دنبالِ منوست، نه
  نشانی و «رستوران‌های مشابه».
- **چرا ساب‌دامین (`menu.rezervno.ir`) نگرفتیم:** به DNS و گواهیِ جدا نیاز دارد و یک
  میزبانِ دومِ ایندکس‌پذیر می‌سازد که باید با canonical مهار شود. همین مسیر روی همان
  میزبان، صفرِ کارِ زیرساختی می‌خواهد.
- **canonical:** صفحه‌ی منو **self-canonical** است، نه اشاره به `/r/{slug}`. محتوایش
  (منویِ کاملِ دسته‌بندی‌شده با توضیح و عکس) در صفحه‌ی رستوران تکرار نمی‌شود — آنجا فقط
  ۱۲ آیتمِ اول پیش‌نمایش می‌شود — پس صفحه‌ی نازکِ تکراری نیست.
- **منویِ خالی → `noindex, follow`:** رستورانی که هنوز منو ثبت نکرده صفحه‌ی بی‌محتوا
  دارد. با ثبتِ اولین آیتم، ISR خودش ایندکس‌پذیرش می‌کند.

**محلی (بدونِ DNS):** `http://localhost:3100/r/{slug}/menu`.

## اجرا (محلی)
```bash
cd apps/seo
npm install
SEO_API_BASE=http://localhost:3000 npm run dev   # http://localhost:3100
npm run build && npm start                        # تولید
npm test                                          # تست‌های خالصِ schema/hours/grouping
```

## پیکربندی
- `SEO_API_BASE` — آدرسِ پایه‌ی `api/` رزرونو (مثلِ `https://api.rezervno.ir`)، بدونِ اسلشِ انتهایی.
  اگر تنظیم نشود، صفحات به‌جای داده حالتِ خالی/۴۰۴ می‌دهند و **build همچنان سبز است** —
  عمدی: یک قطعیِ API نباید دیپلوی را هم زمین بزند.
- `NEXT_PUBLIC_SITE_URL` (سمتِ **api**) — دامنه‌ای که داخلِ QR می‌رود. در staging حتماً
  ست کن، وگرنه QRِ محیطِ تست به دامنه‌ی تولید اشاره می‌کند.

## فونت
Vazirmatn **self-hosted** از `public/fonts/vazirmatn-var.woff2` با `@font-face` در
`app/globals.css`. تا ۲۰۲۶-۰۸-۱۹ این اپ **هیچ فایلِ CSSی نداشت** در حالی که
`layout.tsx` نامِ `Vazirmatn` را ست می‌کرد — یعنی فونت بی‌صدا روی sans-serifِ سیستم
می‌افتاد. هرگز به Google Fonts برنگرد: `fonts.googleapis.com` در ایران در دسترس نیست.

## دیپلوی
یک **پروژه‌ی Vercelِ مستقل**، Root Directory = `apps/seo`، framework = Next.js (`vercel.json`).
روی دامنه‌ی اصلی، این مسیرها باید به این اپ rewrite شوند:

```
/r/*        /city/*        /cuisine/*        /sitemap.xml        /robots.txt
```

بقیه‌ی مسیرها دستِ اپ‌های دیگرند. اگر API در دسترس نباشد: صفحاتِ رستوران/منو ۴۰۴
می‌دهند، صفحه‌ی اصلی بدونِ فهرستِ شهرها رندر می‌شود، و sitemap فقط صفحه‌ی اصلی را دارد.

## وضعیت (۲۰۲۶-۰۸-۱۹)
- ✅ `/r/{slug}` با SSR/ISR، JSON-LD (Restaurant + Menu + Breadcrumb + FAQ)، ساعتِ کاری، گالری
- ✅ `/r/{slug}/menu` — منویِ موبایل‌محورِ QR، بدونِ جاوااسکریپتِ کلاینت
- ✅ `/city/{c}`، `/cuisine/{c}`، sitemap و robotsِ پویا، صفحه‌ی اصلیِ hub
- ⏳ بعدی: `generateSitemaps` برایِ ۵۰k+ رستوران؛ تصویرِ اختصاصیِ OG برایِ صفحه‌ی منو
