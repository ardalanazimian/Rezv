## ۲) بدهیِ ساختاری
1. **`any`-castها (۳۲):** عمدتاً روی مرزِ Prisma/JWT/generic؛ باید با typeهای صریح یا genericِ امن
   جایگزین شوند تا ایمنیِ نوع در refactorهای بعدی حفظ شود. (سطح متوسط)
2. **۴ `console.*`:** یکدست‌سازی با `logger` ساخت‌یافته (trace/level). (سطح پایین)
3. **صفِ Postgres:** بدهیِ «مقیاس» نه «کیفیت» — در مقیاسِ فعلی درست است، در مقیاسِ بزرگ باید مهاجرت کند
   (به PERFORMANCE/PRODUCTION_READINESS ارجاع). (سطح متوسط، آینده‌نگر)
4. **لایه‌ی AI heuristic:** `ai`/`customer-insights`/`rfm`/`fraud` مبتنی بر قاعده‌اند نه مدلِ آموزش‌دیده؛
   اگر «AI واقعی» هدفِ محصول است، این بدهیِ قابلیت است نه باگ (به BACKEND_FINAL). (سطح متوسط)
5. **پوششِ شِمای ورودی:** ~۲۶ routeِ بدونِ شِمای صریح (اغلب GETِ ساده) — افزودنِ `parseQuery` حتی برای
   GETهای پارامتری، سطحِ یکدستی را بالا می‌برد. (سطح پایین)
