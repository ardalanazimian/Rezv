### گزینه‌ی الف — افشا در سه نقطه

**متنِ پیشنهادی برای نقطه‌ی ۱** (تنها نقطه‌ای که امروز داده دارد):

> لغوِ رایگان تا ۲۴ ساعت پیش از زمانِ رزرو. دیرتر از آن، یک تخلف در سابقه‌ات ثبت
> می‌شود و نشانِ اعتبارت پایین می‌آید — این نشان به رستوران‌ها هم نشان داده می‌شود.

- عدد از `fmtFa(r.freeCancelHours)` می‌آید، نه هاردکد.
- اگر `freeCancelHours === null` بود، **هیچ‌چیز رندر نشود** (سکوت، نه حدس) — همان
  قاعده‌ای که `depositLabel` در همین فایل رعایت می‌کند.

**متنِ پیشنهادی برای نقطه‌ی ۳** (نیازمندِ ساختِ دیالوگِ تازه):

> این رزرو کمتر از ۲۴ ساعت تا زمانش مانده. اگر الان لغو کنی، یک تخلف در سابقه‌ات
> ثبت می‌شود و نشانِ اعتبارت پایین می‌آید.
> [لغوِ رزرو]  [بی‌خیال]

**هزینه‌ی واقعیِ گزینه‌ی الف:** تغییرِ قراردادِ `GET /me/reservations` (افزودنِ
`free_cancel_hours`) + ساختِ یک دیالوگِ تأییدِ تازه که امروز وجود ندارد + متن در سه
نقطه — یعنی تغییر در بک‌اند، در جریانِ لغو، و در UI، همه پیش از لانچ.

### گزینه‌ی ب — خاموش‌کردنِ موقتِ جریمه

یک بلوک در `api/src/lib/economy.ts:111-114`:

```js
// فعلی
return late
  ? { score: 35, addsStrike: true,  label: 'reservation_cancelled_late' }
  : { score: 85, addsStrike: false, label: 'reservation_cancelled_in_window' };

// پیشنهادی (موقت، تا افشای کاملِ UI)
return late
  ? { score: 85, addsStrike: false, label: 'reservation_cancelled_late' }
  : { score: 85, addsStrike: false, label: 'reservation_cancelled_in_window' };
```

برچسبِ `reservation_cancelled_late` **عمداً می‌ماند** تا اندازه‌گیری از دست نرود؛
فقط جریمه‌ی پنهان برداشته می‌شود — هم strike و هم افتِ امتیازِ ۸۵ به ۳۵.

### توصیه‌ی من: **گزینه‌ی ب**

مهم‌ترین نقطه‌ی افشا (لحظه‌ی لغو) دقیقاً همان‌جایی است که نه داده دارد و نه دیالوگ.
اگر فقط شیتِ رزرو افشا شود، کسی که لغو می‌کند همچنان بی‌خبر جریمه می‌شود — و این از
هر دو حالتِ کامل بدتر است، چون ظاهرش «اعلام کردیم» است در حالی که فردِ متضرر هرگز
آن را ندیده.

گزینه‌ی ب یک فایل، یک بلوک، و کاملاً برگشت‌پذیر است. پس از لانچ، افشای کامل
(بک‌اند + دیالوگ + هر سه متن) می‌آید و آن‌وقت جریمه برمی‌گردد.
