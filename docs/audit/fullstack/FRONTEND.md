### مکانیزم

`loadRestaurants()` در `apps/customer/js/api.js:341-371` سه حالت دارد، ولی فقط
**دو** شرط می‌نویسد:

```js
if (list && list.length) { … }        // دادهٔ واقعی
if (res.ok) { …; return []; }         // ۲۰۰ ولی خالی → حالتِ خالیِ صادق
API.online = false;
if (res.offline) console.info(…);     // ← offline فقط برای پیام، نه برای شاخه
return R_SAMPLE;                      // ← هر چیزِ دیگر، از جمله ۵۰۰
```

شاخهٔ آخر روی `!res.ok` می‌افتد، نه روی `res.offline`. و این دو یکی نیستند:

| منبع | مقدار | معنی |
|---|---|---|
| `api-core.js:50-52` | `{ok:false, status, data, error}` | پاسخِ HTTPِ خطا — **سرور زنده است** |
| `api-core.js:54-57` | `{ok:false, offline:true}` | شکستِ شبکه/تایم‌اوت/`file:` |
| `api.js:66-68` | همان دو را بدون تغییر عبور می‌دهد | — |

یعنی ۵۰۰، ۵۰۲، ۵۰۳، ۴۲۹ و ۴۰۳ همگی به `return R_SAMPLE` می‌رسند — در حالی که
کامنتِ بالای همان خط صریحاً ادعا می‌کند «فقط اینجا دادهٔ نمونه مجاز است: بک‌اند
واقعاً در دسترس نیست (`file://`، تایم‌اوت، یا خطای شبکه)». **کد آن ادعا را
پیاده نکرده است.**

### اثباتِ runtime

هارنس: `scratchpad/demo-trap-proof.mjs` — سرورِ استاتیکِ محلی روی `localhost:18091`
که `apps/customer` را same-origin سرو می‌کند و `/api/v1/*` را طبقِ حالت پاسخ
می‌دهد؛ مرورگرِ واقعی (chromium 1.62.1، Service Worker بلاک‌شده).

| حالت | پاسخِ `/api/v1/restaurants` | `[DEMO]` در DOM | دادهٔ کنترلِ واقعی |
|---|---|---|---|
| **A** | `500 {error:{code:INTERNAL}}` | **۱۸ بار** | — |
| **B** (کنترل) | `200 {items:[]}` | ۰ | — |
| **C** (کنترل) | `200 {items:[یک رستورانِ واقعی]}` | ۰ | ✓ رندر شد |

هر دو کنترل درست رفتار می‌کنند، پس نتیجهٔ A مصنوعِ هارنس نیست.

خروجیِ خامِ حالتِ A — همان چیزی که کاربر می‌بیند:

```
۶ رستوران فعال · امروز · ۲ نفر
🌿 [DEMO] کافه‌رستوران ویستا …
```

سرآیند «۶ رستوران فعال» می‌گوید، شش کارتِ جعلی نشان می‌دهد، و در کنسول **هیچ
پیامی دربارهٔ دادهٔ نمونه نیست** (چون `res.offline` در این حالت false است و
`console.info` اجرا نمی‌شود). تنها ردِ ماجرا سه خطِ `Failed to load resource`
است که کاربر نمی‌بیند.

### چرا این کلاسِ باگ، نه یک باگِ تکی

خودِ اپ گیتِ درست را می‌شناسد و **در دو جای دیگر درست به کار برده**:

| محل | گیت | حکم |
|---|---|---|
| `features/notifications.js:40` | `isOfflineDemo() && Array.isArray(TRIPS)` | ✅ درست |
| `reservation.js:121` | `isOfflineDemo() ? TRIPS : []` | ✅ درست |

`isOfflineDemo()` قفل‌اند و فقط `loadRestaurants` روی نتیجهٔ درخواست. این یک
ناسازگاری با قراردادِ خودِ اپ است، نه یک تصمیمِ طراحی.

### سابقهٔ همین فایل

کامنتِ `api.js:352-360` می‌گوید نسخهٔ قبلی **هم** همین کلاس را داشت: `۲۰۰` با
`items:[]` هم به `R_SAMPLE` می‌رسید و به کاربرِ واقعی شش رستورانِ `[DEMO]` نشان
می‌داد. آن حالت بسته شد؛ حالتِ «سرور زنده ولی خطا» باز ماند.

### دامنه
