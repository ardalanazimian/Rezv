## The claim fixed

`api/tests/points-ledger-append-only.integration.test.mts:134` (on `99065a7`). The FK-RESTRICT
retention test called `assert.rejects(fn, '<Persian sentence>')`. Node treats a **string** second
argument as the assertion's own failure message, not as an expectation. So the test passed for
*any* rejection. `tools/check-rejects-matcher.mjs` flagged it, exit 1 (CEO P0-1; Red Team M-09
rates it hygiene, not load-bearing).

## Root cause and class

- **Root cause:** Node's `assert.rejects(fn, error?, message?)` overloads its second argument, and
  a string there silently becomes the message. The sentence reads like an expectation to a human
  reviewer.
- **Class:** assertions that prove "something failed" without proving *what* failed. They stay
  green when the failure identity changes.
- **Siblings:** `node tools/check-rejects-matcher.mjs --report` on `99065a7` counts **113 of 176**
  `assert.rejects` / `assert.throws` calls as weak (64%, 20 files), 28 of them in the string
  form. By an earlier reviewer + CEO decision (header of that tool), the gate ratchets on the
  **diff** only and old calls tighten when touched. This fix follows that decision and does not
  sweep the other 112. They are counted, not fixed.

## The diff

One call. The second argument became a validation function asserting the identity measured
live: `code === 'P2003'` and `meta.field_name` starts with `points_ledger_user_id_fkey`. The
explanatory sentence moved to the third argument, where Node reads it as the message.
