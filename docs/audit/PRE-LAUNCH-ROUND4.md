## ۴. نقطه‌ی ۳ — دیالوگِ تأیید، فقط برای مسیرِ دیرهنگام

`apps/customer/js/features/trips.js`

```
cancelTrip(code, btn)
  ├─ isLateCancel(trip) === false → undoSnackِ فعلی، دست‌نخورده
  └─ isLateCancel(trip) === true  → openLateCancelConfirm(...)
```

اصلاحِ شما رعایت شد: **اصطکاک فقط جایی اضافه شد که پیامدِ واقعی دارد.** مسیرِ داخلِ
پنجره حتی یک خط هم تغییر نکرد.

**a11y از الگویِ موجود آمد، نه الگویِ تازه.** `openSheet` (در `auth.js:235`) از قبل
اینها را می‌دهد: `role="dialog"` و `aria-modal="true"` رویِ `#sheet`
(`index.html:240`)، تلهٔ فوکوسِ Tab/Shift+Tab، بستن با Escape، و بازگرداندنِ فوکوس
به عنصرِ قبلی.

**چهار حالتِ دیالوگ:** پرسش · در حالِ ارسال (دکمه قفل، متنِ «در حالِ لغو…») · خطا
(پیامِ سرور داخلِ دیالوگ + دکمه باز می‌گردد) · موفق (بسته‌شدن + توست + رفرشِ فهرست).
«خالی» برای یک دیالوگِ تأیید موضوعیت ندارد.

### یک باگ که خودم ساختم و همان تست گرفتش

برچسبِ دسترس‌پذیرِ ظرف را برای دیالوگ عوض کردم («تأیید لغو رزرو» به‌جای «جزئیات
رزرو»)، ولی اول فقط در مسیرِ موفق بازش می‌گرداندم. **سه مسیرِ بستن وجود دارد** —
دکمه‌ی «بی‌خیال»، Escape، و کلیک رویِ overlay که در `index.html:240` مستقیم
`closeSheet()` را صدا می‌زند. یعنی شیتِ **بعدی** با نامِ «تأیید لغو رزرو» باز می‌شد:
یک نامِ دسترس‌پذیرِ دروغ.

رفع با یک `MutationObserver` رویِ کلاسِ `show` که هر سه مسیر را می‌پوشاند و خودش را
`disconnect` می‌کند. تست هم ادعایش را دارد.
