# عکاسیِ وب‌سایت — چه بگیریم و کجا بگذاریم

سایت تا امروز **هیچ عکسِ واقعی نداشت**؛ همه‌چیز از شکل و آیکن ساخته شده بود.
این تنها بزرگ‌ترین چیزی است که یک لندینگ‌پیج را از «ساختِ سریع» به «برندِ
واقعی» می‌برد. زیرساختش حالا آماده است — این سند می‌گوید چه چیزی لازم است.

> **چرا خودم عکس نگذاشتم:** دسترسیِ شبکه‌ی این محیط به سرویس‌های عکس
> (Unsplash، Pexels، Pixabay، ویکی‌مدیا) بسته است. مهم‌تر از آن، عکسِ استاکِ
> رستورانِ دیگران روی سایتی که رستوران می‌فروشد، اگر شبیهِ «مشتریانِ ما»
> دیده شود گمراه‌کننده است. عکسِ واقعیِ خودتان بی‌نهایت بهتر از هر استاکی
> کار می‌کند.

## فهرستِ عکس‌ها (به‌ترتیبِ اهمیت)

| # | جای استفاده | نسبت | حداقلِ عرض | چه چیزی |
|---|---|---|---|---|
| ۱ | بلوکِ `scene` — تمام‌عرض | ۲۱:۹ افقی | ۲۴۰۰px | سالن در ساعتِ شلوغی. آدم‌ها در قاب باشند ولی چهره‌ها واضح نه. نورِ گرمِ عصر. |
| ۲ | `gallery` — خانه‌ی بزرگ | مربع/۴:۳ | ۱۶۰۰px | نمای معرفِ فضا. همان قابی که اگر یک عکس داشتید، همان را نشان می‌دادید. |
| ۳–۶ | `gallery` — خانه‌های کوچک | مربع | ۸۰۰px | یک بشقاب از بالا، دستِ سرآشپز، جزئیاتِ میز، نوشیدنی. |
| ۷ | `photosplit` | ۳:۴ عمودی | ۱۲۰۰px | یک آدم در حالِ کار — مدیر پشتِ پنل، یا میزبان دمِ در. |
| ۸ | تصویرِ اشتراک‌گذاری (OG) | ۱٫۹۱:۱ | ۱۲۰۰×۶۳۰ | همان عکسِ ۱ با برشِ دیگر. |

### چند قاعده که تفاوت را می‌سازد

- **نورِ طبیعی یا نورِ گرمِ رستوران.** فلاشِ مستقیم، عکس را شبیهِ عکسِ منو
  در اپلیکیشنِ سفارشِ غذا می‌کند.
- **افقی برای `scene`، عمودی برای `photosplit`.** عکسِ افقیِ کنارِ متن همیشه
  شبیهِ بنرِ تبلیغاتی می‌شود.
- **فضای خالی در قاب.** روی عکسِ `scene` متن می‌نشیند؛ اگر کلِ قاب پر باشد
  متن جا ندارد. سمتِ راستِ کادر (شروعِ متن در فارسی) را خلوت بگذارید.
- **چهره‌ها:** اگر چهره‌ی مشتری تشخیص‌پذیر است، رضایتِ کتبی بگیرید.

## گذاشتنِ عکس‌ها

### ۱) فایل‌ها

```
apps/landing/public/photos/
  scene-salon.jpg
  gallery-01.jpg  …  gallery-05.jpg
  portrait-host.jpg
```

پیش از کپی، اندازه را کم کنید (بیش از ۲۵۶۰px عرض بی‌فایده است) و کیفیت را
روی ~۸۰ بگذارید. Next خودش AVIF/WebP و اندازه‌های واکنش‌گرا می‌سازد، پس
لازم نیست چند نسخه بسازید.

### ۲) محتوا

در `shared/content/site-content.json` (و بعد `sh tools/sync-design-system.sh`)
یا مستقیم از استودیوی سایت:

```json
{
  "type": "scene",
  "height": "tall",
  "eyebrow": "شبِ سرویس",
  "title": "جایی که رزرو به یک شبِ خوب تبدیل می‌شود",
  "image": {
    "src": "/photos/scene-salon.jpg",
    "alt": "سالنِ رستوران در ساعتِ شلوغیِ شب",
    "focal": "50% 35%"
  }
}
```

`focal` نقطه‌ای است که هنگامِ برش هرگز نباید حذف شود (پیش‌فرض وسط). اگر
سوژه پایینِ قاب است `50% 70%` بگذارید.

### ۳) گالری

```json
{
  "type": "gallery",
  "items": [
    { "image": { "src": "/photos/gallery-01.jpg", "alt": "نمای سالن" } },
    { "image": { "src": "/photos/gallery-02.jpg", "alt": "بشقابِ ویژه" }, "caption": "خورشتِ شب" }
  ]
}
```

اولین آیتم خانه‌ی بزرگ است. تا پنج آیتم نشان داده می‌شود.

## عکسِ رستوران‌های واقعی

عکسی که رستوران‌ها از پنلِ کسب‌وکار آپلود می‌کنند (و در پنلِ شرکت تأیید
می‌شود) از `/api/v1/media/...` سرو می‌شود و در `next.config.js` مجاز شده
است. یعنی همان عکس‌ها را می‌شود مستقیم در گالریِ سایت هم استفاده کرد:

```json
{ "image": { "src": "https://api.rezervno.ir/api/v1/media/2026/08/<uuid>.jpg", "alt": "…" } }
```

⚠️ فقط عکسِ **تأییدشده** و فقط با اجازه‌ی همان رستوران. عکسِ مشتری روی
صفحه‌ی فروشِ ما، بدونِ اجازه، هم حقوقی مسئله دارد هم اخلاقی.

## تا وقتی عکسی نیست

بلوک‌ها خالی نمی‌مانند و نمی‌شکنند: جای هر عکس با برچسبِ روشن («جای عکس»،
«عکسِ اصلیِ فضا») و بافتِ راه‌راه نشان داده می‌شود. این عمدی است — یک تصویرِ
ساختگی که وانمود کند عکسِ واقعی است، هم بازدیدکننده را گمراه می‌کند و هم
باعث می‌شود کسی یادش برود عکسِ واقعی بگذارد.
